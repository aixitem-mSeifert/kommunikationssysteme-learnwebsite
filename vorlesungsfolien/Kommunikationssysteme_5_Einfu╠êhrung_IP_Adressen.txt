Die Wegwahl im Internet
Protokoll 
• Die IP-Implementierung eines Rechners oder Router-Systems entscheidet, wohin ein 
Datagramm übertragen wird
• Basis für diese Entscheidung sind Routing/Forwarding-Tabellen
• Diese Tabellen werden mittels der Informationen aus dem IP-Header durchsucht
• Normalerweise wird hierbei ausschließlich die Zieladresse des Datagramms verwendet
Merke: Jeder Router trifft diese Entscheidung für jedes Paket/Datagramm und zwar 
unabhängig von den anderen Routern. Basis ist die Zieladresse des Datagramms.

• Kann das Datagramm direkt über Verfahren der Sicherungsschicht an das Zielsystem 
ausgeliefert werden, so wird das Paket zur Übertragung an die Sicherungsschicht 
übergeben– Beide Systeme befinden sich im „gleichen Netz“ sein – Der Router/Sender muss  die HW-Adresse der Schicht 2 in Erfahrung bringen, um der Netzwerkkarte 
mitzuteilen, an wen das Datagramm übertragen werden soll

direkt erreichbare Router das Paket zur Weiterleitung erhält (analog zum ersten Fall)– Das Paket wird an die Sicherungsschicht zur Übertragung an den selektierten Router geleitet (indirekte

Merke: 
• Router haben mehr als eine Netzwerkkarte und somit mehr als eine IP-Adresse. IP
Adressen adressieren somit eigentlich nicht Rechner als singuläre Entität, sondern einen 
Netzwerkzugang eines Rechners
• Auch End-Systeme können über mehrere IP-Adressen verfügen. Anschaulich ist die IP
Adresse die Betriebssystemanbindung der Netzwerkkarte an ein IP-(Teil)netz
• Auch wenn eine Netzwerkkarte eine IP-Adresse hat, so besitzt sie trotzdem auch eine HW
Adresse, über die die Kommunikation der Sicherungsschicht läuft. Diese ist eindeutig (im 
konkreten Netz) und unabhängig von der Einbettung in die IP-Topologie
• Faktisch haben wir also eine Adresse, die die Kommunikation innerhalb eines Netzes für 
eine bestimmte Sicherungsschicht regelt und eine Adresse, die die Ziele topologisch 
systematisiert und so Netze und Endsysteme in Netzen adressiert

IP
Adressierung (v4) 
Topologische Struktur
• Am Internet angeschlossene Systeme werden über eine weltweit eindeutige 
IP-Adresse identifiziert (Ausnahme: private Netze, Multicast und Anycast
Adressen)
• IPv4-Adressen sind 32 Bit lang 
• IPv4-Adressen haben eine bestimmte Struktur: 
• Der vordere Teil bestimmt die Netzwerk-Adresse für das Netz (z.B. 140.201.10 
.100), in dem sich der Rechner befindet. Innerhalb dieses Netzes kann eine direkte 
Kommunikation mittels der Sicherungsschicht geschehen
• Der hintere Teil bestimmt die Rechner-Adresse im gegebenen Netz für einen 
Kommunikationsendpunkt, einen Host (z.B. 140.201.10 .100)

• Niemand hatte damals mit einem derart starken Wachstum des Internets gerechnet (sonst hätte

• Allzu viele Class A-Adressen wurden in den ersten Internetjahren vergeben

: wenn 500 Geräte in einem Unternehmen angeschlossen werden sollen,

Ein weiteres Problem...
• Router verbinden immer Netze, wodurch beispielsweise unterschiedliche Netztechniken in den einzelnen 
Netzen eingesetzt werden können
• Damit erfordern sie aber auch eine Änderung der IP-Netzwerkadresse, wenn sie in mehreren Netzen sein 
sollen
• Router trennen damit Netze, was diesen eine verbesserte Struktur gibt
• Erst durch Router können also relativ einfach und skalierbar unterschiedlichste Netztechnologien eingesetzt 
werden
• Institutionen mit größeren Netzen möchten auch intern Router verwenden (strukturierte Netzplanung)
• Noch haben diese Institution aber immer nur „eine“ an sie vergebene Netzadresse 
Merke: 
Möchte man unterschiedliche Netztechnologien (Schicht 1-2) einsetzen, die nicht einfach miteinander kombiniert 
werden können, so sind Router eine sinnige Lösung hierfür und damit mehrere IP-Netzwerkadressen

Beachten Sie...
• Subnetzmasken 
• können Netze unterteilen
• erschweren ggf. das Erkennen der Netzadressteile (nicht für den Rechner)
• haben lokale Bedeutung (auf dem System auf dem sie konfiguriert sind)
• gehören zur systematischen Netzplanung hinzu  
• Innerhalb eines Subnetzes sollte die Rechneradresse (binär) „0...0“ und die Rechneradresse 
(binär)  „1....1“ nicht verwendet werden 
Falsch konfigurierte Subnetzmasken führen dazu, dass die IP-Kommunikation zumeist nicht mehr 
möglich ist
