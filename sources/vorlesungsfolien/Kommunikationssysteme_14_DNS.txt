DNS 
Konzept
1. DNS handhabt die Abbildung von Rechnernamen auf Adressen (und weitere Dienste)
2. DNS ist eine verteilte Datenbank, d.h. 
• DNS-Server verwalten nur einen Teil der Rechner im Internet
• Erst der Verbund aus allen Servern ergibt einen vollständigen Namensraum
• Die Struktur des verwendeten Namensraums der Datenbank gibt eine administrative Einteilung des Internets 
wieder – Bereiche (Zonen) verwalten Ihre Adressen
• die einzelnen Zonen unterliegen somit einer lokalen Kontrolle
• Zonen sind miteinander verbunden und werden im Namensraum durch Übergangspunkte definiert
4. Daten jedes lokalen Bereichs werden mittels einer Client/Server-Architektur im gesamten Netzwerk verfügbar gemacht
5. Robustheit und Geschwindigkeit des Systems werden durch Replikation der Daten und Zwischenspeicherung (Caching) 
erreicht
6. Hauptkomponenten:
• Name Server: Server, die  Informationen über einen Bereich der Datenbank verwalten
• Resolver: Clients, die Anfragen an die Server stellen

DNS
Zonen
• Eine Zone ist ein autarker Bereich im DNS-Namensraum
• Zur Einrichtung einer Zone muss der übergeordnete Knoten davon 
überzeugt werden, die Verwaltung zu delegieren
• Eine Zone ist ein kontinuierlicher Namensraum mit eigener Datenbank - Knoten im Baum (Bezeichnung darf maximal 63 Zeichen lang sein)- Bis zu 127 Ebenen (ohne Bezeichnung)
• Jede Zone hat einen primären und beliebig viele sekundäre 
Nameserver (NS)- Jeder NS kennt zunächst nur (s)einen Ausschnitt des gesamten Namensraums - Jeder NS kennt alle IP-Adressen seiner direkt untergeordneten Sub-Domains der eigenen 
Zone- Sekundäre NS führen ein periodisches Update („Zonentransfer“) ihrer Datenbasis durch 
(vollständige Datenbestand des primären NS wird transferiert)    (Master-Slave-Prinzip)

DNS
Attacken
• DNS ist ein durchaus kritischer Dienst
• Da er zumeist nur UDP verwendet, ist er häufig Angriffsziel:
• DNS ID Hacking: Anfragen werden oft nur über eine Query ID geschützt, d.h. der Client 
erwartet nicht nur die Auflösung, sondern auch noch eine spezielle assoziierte ID. Wenn 
diese nicht vom Netz abgegriffen werden kann, so muss man sie erraten
• DNS spoofing: Hier beantwortet ein falscher DNS-Server die Anfrage. Hier muss die ID 
verwendet werden. Auch wird die falsche IP, also die des eigentlich richtigen Servers 
angegeben (was von den Providern zu unterbinden ist)
• DNS Cache Poisoning: Hier wird versucht, einen eigentlich korrekten DNS-Server zu 
„verseuchen“. Idee ist, den Cache falsch zu füllen
